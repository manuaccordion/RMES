★ Big Picture — daily landing

Today's snapshot, with a chart of the last/next days and the totals for each of the 4 properties.

  • Day chart: bars = RN per day. Click a bar to drill into that day.
  • Property tiles: revenue OTB, OCC, ADR. When All is selected, you see 4 tiles side by side.
  • Channel share donut: outer ring = current year, inner ring = STLY. In All mode, 4 mini-donuts (one per property). The delta arrows (▲/▼) compare current share vs STLY share. Channel name normalization: raw channel manager labels are folded into canonical buckets so the YoY comparison actually matches. BOOKINGXML, MOBILESITE → Booking; EXPEDIA, Hotels.com, Orbitz, Expedia Affilia → Expedia; CTRIPV4 → Ctrip; Beddy, Krossbooking, FrontOffice, PrenMan, Booking Engine, walk-in → Direct (one label for "no-OTA, booked through the property PMS"). If a property has no bookings in the dataset, the donut shows "No bookings in dataset for this property".
① Sell Strategy — the main daily tab

One row per stay-date, looking forward. Where you decide the price to load on Beddy.

Columns, left to right:

  • Date · Event · DoW — the stay-date, the event name (if any), and the day of the week. The orange tint is only on these 3 cells: indicates the Expedia search pressure for that day (faint = low demand, more saturated = high demand). All the other columns stay neutral so numbers are easy to read. Event names come from EVENTS_CSV in data.js — if you don't see them, data.js needs to be regenerated by Claude Code.
  • OTB to date — RN booked, OCC, ADR for that night.
  • Pickup 1d — net pickup in the last 24h: New, Cancelled, ΔRN, ADR.
  • STLY (−364d) — what we had at the same point of the cycle last year (same day of the week).
  • Pickup STLY 1d — pickup last year on the same booking-day (today−364).
  • RMES last update — yesterday's RMES price (Beddy €). Shows the final price and Δ€ vs that day's reference, centered. Click the cell to open the full calculation detail.
  • RMES today — today's RMES suggestion. Same format (price + Δ€), centered. The ✓ button accepts the suggestion as the new current reference. Click anywhere else in the cell to open the detail. The full % variation is in the tooltip. You can accept/override RMES as many times as you want.
  • Beddy — the price currently loaded in the PMS (read-only), if available.
  • Rate Shopper — Mine w/RMES · Mine · Compset, all in Expedia space, with the market rank (1 = cheapest). Note: any Expedia value < 10 € is now filtered out (it's a minimum-stay number leaked into the price column, not a real rate).
  • Base Price — the structural starting price for the day. Accepted by default: shown in green with a ✓ icon, meaning it's already the active price for that day, no action required. Touch it only occasionally if something looks off: 🖋 overrides a single day, ↺ resets. For a range use Override by period above the table.

Override by period: panel above the table — set From / To, then 🖋 Base Price to override a Base for a whole range, or ✓ Accept RMES to accept RMES for a whole range. ↺ Reset period wipes overrides on the range.

How to read a row at a glance. The Base Price column (green ✓) is your starting price for the day, already active. The RMES today column (orange ✓) is the engine's suggested adjustment — if you agree, click ✓ to make it the new reference; if not, ignore it and the Base Price keeps being the active price. Override the Base only as exception.

② Overview — month-by-month, including forecast

One row per month, looking forward 12 months. Contains the forecast and the historical breakdown by Source and Channel.

Top KPIs: YTD + Forecast Revenue, Final LY 2025 reference, Δ vs Final LY, OTB already acquired.

Monthly KPI table (left to right):

  • Current OTB — OCC / ADR / Revenue already on the books.
  • STLY (−364d) — what was on the books exactly 364 days ago for the same stay-month. Used to read the pace.
  • Final LY 2025 — actual close last year (reference for the forecast).
  • YTD + Forecast (live) — past months = actuals; current month = actuals up to yesterday + forecast for the rest; future months = forecast.
  • Month-1st snapshot — forecast frozen on day 1 of the month and the live Δ% vs it (how well the early forecast tracked).
  • Budget — budget OCC / ADR / Revenue from the budget files.
  • KPIs for achievement — Diff (Fct−OTB), €/day to close (time-aware), €/day pickup 7d (cur vs STLY), % Achievement.

Source / Channel tables below: filter with the month pills above them — yearly view by default. Source = booking provenance (where the guest came from); Channel = direct booking channel (Booking, Beddy, Expedia, …).

Booking window chart at the bottom: rolling 12 closed months, mix of bookings and average ADR by lead-time window.

③ Pickup Matrix — booking-date vs stay-date

Heatmap to read how booking-date and stay-date are connected. Rows = booking month, columns = stay month. Each cell = RN booked in that month for stays in that other month.

Useful to see lead time at a glance and spot which months are "booking" right now for which future months.

④ CXLTrend — cancellations

Cancellation rate and lost revenue trend. Lets you spot anomalous channels or pricing plans (e.g. a non-refundable price plan with abnormal cancellations).

⑤ OCC by Room Type

OCC broken down by Room Type. Used to spot RTs that book early vs late and the actual price/RT mix.

⑥ Rate Shopper — competitor prices

Daily prices from the Expedia compset for each property. For each competitor set a weight (0% = excluded from the average, 100% = full weight) and an offset in € (e.g. −10 = "I want to stay €10 below this competitor"). These produce two different numbers used in two different places:

• Expedia Goal Value = weighted compset price WITH the per-competitor offsets — your desired online positioning. It is used only as the maximum cap on the Base Price (the Base Price can never exceed it; the minimum stays the Floor Rate).

• Weighted Expedia Compset = weighted compset price WITHOUT offsets (weights only) — a neutral "where am I vs the market" reference. It is used by the RMES factors (D · Online Pricing and E · Demand Expedia), where offsets must not interfere.

Sanity filter: any Expedia value below 10 € is treated as missing (it's the minimum-stay number leaked into the price column, not a real rate). Floor across the 4 properties is ≥ 100 €.

⑦ RMES — pricing engine configuration

The page where you tune the pricing engine. Switch property at the top: weights, cap, Base Price parameters and LMF are independent per property; event weights are shared across properties.

Block ① — Weights of the 5 RMES factors

How much each of the 5 factors contributes to the daily adjustment. Default: 20% × 5 = 100%.

  • A · OCC pace — current OCC / STLY OCC
  • B · ADR pace — current ADR / STLY ADR
  • C · vs Compset — my Expedia price vs compset average
  • D · Online Pricing — pace of compset price moves
  • E · AirDNA — market signal from AirDNA

Internal cap on each factor: ±50%. The sum of weights is normalized automatically.

Block ② — RMES total cap

Final guard-rail: the RMES suggested price always stays within ±cap% of the current reference. Default = 30% (suggestion: leave it at 20-30%, anything more risks sharp swings).

Block ③ — ✨ Event Factor

For each event (loaded from EVENTS_CSV) you set a weight from −10% to +10%. On days that match the event, the RMES price is multiplied by (1 + event%). Positive = premium, negative = discount, zero = no effect.

Weights are shared across all 4 properties: an event like "Pitti" has the same weight everywhere.

If the box shows "No events loaded": EVENTS_CSV is missing or empty in data.js. Regenerate data.js via Claude Code.

⚡ Base Price block

The Base Price is the structural starting price the RMES suggestion sits on top of. It is computed once per stay-date and then frozen. Five steps, left to right:

  1. Historical anchor (LY median ADR) — for the target date the system takes every day with the same day-of-week and the same month across the last two years (2024 + 2025), collects the ADR actually earned on the base room type only on those days, and takes the median (robust to one-off outliers). Two things to know: (a) every booking is counted net of OTA markup — Booking/Expedia/Airbnb prices are divided by their markup so all channels are compared in Beddy-equivalent, while direct/Beddy/Krossbooking bookings are used as-is; (b) "obs" counts bookings (room-stays), not days — a single day can hold several bookings (one per occupied room), so the number is normally higher than the number of matching days. If fewer than 3 bookings exist, it widens to the whole month. So "LY ADR" is not a single day last year — it is the typical earned ADR for that weekday-and-month pattern, on the base room type, in Beddy space.
  2. × target growth — anchor multiplied by (1 + the month's target growth %).
  3. Expedia Goal Value cap — the result is capped at the Goal Value (weighted compset price WITH per-competitor offsets = your desired online positioning). The Base Price can never exceed the Goal Value.
  4. Anchor guard-rail — bounded within ±50% of the annual Anchor Price, to avoid wild swings.
  5. Floor — never below the property Floor Rate (the hard minimum).

A protection also lifts the anchor to at least 70% of the Anchor Price when history is too thin, so the Base Price never collapses.

Configurable in this block: Ⓑ Anchor Price (annual, single number per property), target growth % per month, floor, OTA markup (Expedia / Booking / Airbnb), LMF matrix (Last-Minute Factor: extra adjustment at DoW × pickup-window).

Change the Anchor Price → it does not recompute Base Prices already frozen. Use Override by period in Sell Strategy to rewrite them.

You can inspect the full step-by-step build-up for every day and property in the dedicated Base Price tab, and export it to CSV.

Ⓒ Compset competitor weights / offsets

Same compset weights/offsets control as in Rate Shopper, available in the RMES tab too. The weights feed factor D · Online Pricing (via the offset-free Weighted Expedia Compset); the weights + offsets define the Expedia Goal Value that caps the Base Price.

"Apply changes" button

Changes to weights / cap / Base Price / event weights are saved only when you click "Apply changes" at the bottom of the tab. Switch property to edit the others (each property is independent for everything except event weights).

8 · Base Price

A transparent, day-by-day view of how each Base Price is built — the same five steps described in the RMES → Base Price block, shown left to right as columns so you can audit any date.

Pick a property (or All for the four together) and a date range (same logic as Sell Strategy), then Apply. The header row stays visible while you scroll, and hovering any number shows how it was obtained. Columns: LY median ADR · observations (* = widened to the whole month when fewer than 3 bookings on the exact weekday) · ADR used (⬆70% = the anchor was lifted up to 70% of that property's annual Anchor Price — e.g. Firenze Anchor €220 → floor of €154 — to avoid an unrealistically low base when history is thin) · × growth · after growth · Goal Value cap (red ✓cap = the price after growth was above your Goal Value, so it was capped down) · Anchor ±50% (↓max / ↑min = the result hit the guard-rail and was pulled back inside ±50% of the Anchor Price) · Floor (✓ = the Floor Rate raised the price) · final Base Price.

⬇ Export CSV downloads the whole table (every column, every day) for Excel.

☁ Shared state (real-time sync)

RMES decisions (accepted prices, Base Price overrides) and the whole configuration (the 5-factor weights, caps, floor, anchor, target growth, event weights, compset weights/offsets) are shared in real time between everyone who opens the dashboard. When one person accepts a price or changes a setting, the others see it without re-importing anything, on any browser or device.

The chip in the top bar shows the status: ☁ synced = your changes are saved to the shared store and you are seeing everyone's latest state; ⚠ local only = the connection to the shared store is unavailable, so you are working on this browser alone — everything still works and will sync automatically when the connection is back.

If two people change the same thing at the same moment, the last save wins. In practice you almost never edit the exact same date at the exact same second, so this is rarely an issue.

📚 Glossary
OTB
On The Books — bookings already confirmed for a stay-date.
RN
Room Nights = rooms × nights. E.g. 2 rooms × 3 nights = 6 RN.
OCC
Occupancy = RN sold / (rooms × days available).
ADR
Average Daily Rate = revenue / RN sold (net of city tax).
STLY
Same Time Last Year = last year's snapshot at the same point of the cycle. Day-of-week-aligned (today − 364 days = same day of week). Used to compare pace.
Final LY
The full close of last year. Different from STLY: Final LY is "what last year ended up as", STLY is "what was already on the books at this point last year".
Base Price
Structural price per stay-date, frozen, computed once. Source of the RMES suggestion.
Anchor Price
Single annual reference number per property. The Base Price stays within ±50% of it.
RMES delta
Today's adjustment on top of the current reference, computed from the 5 factors + LMF + Event Factor. Capped at ±20% of the reference.
baseRT
The reference Room Type for each property (Camera Matrimoniale Deluxe for Firenze, Bilocale for Condotta, Classic for Alfani, Senape for Davids). Base Price is computed at the baseRT, other RTs inherit Base + monthly supplement.
RT supplement
Historical ADR difference between an RT and the baseRT, split by high / low season. E.g. Suite with Terrace Firenze May = +€70 (high), +€50 (low).
LMF
Last-Minute Factor — adjustment matrix DoW × pickup-window, applied as multiplier to the RMES price.
Channel vs Source
Channel = direct booking channel (Booking, Beddy, Expedia, …). Source = where the guest came from (country, OTA, direct, …).
OTA markup
The mark-up the OTA adds to the loaded price: Expedia 17%, Booking 13%, Airbnb/VRBO 10%. Used to compare across channels in Beddy space.
